# 55-02: REST Endpoints + DTOs + Employee Report Extension

## Objective
Implement REST endpoints and data transfer objects for manual rebooking features, including HR alert integration into employee reports.

## Read First
- `.planning/phases/55-manual-rebooking-hr-alert/55-CONTEXT.md`
- `rest/src/reporting.rs` (existing endpoint structure)
- `service_impl/src/reporting.rs` (to understand how ShortEmployeeReportTO is composed)
- `rest-types/src/employee_report.rs` (current structure of employee report DTOs)

## Acceptance Criteria
- [ ] New REST endpoints created in `rest/src/rebooking.rs`:
  - `POST /rebooking/manual` for manual rebooking
  - `GET /rebooking-suggestions` to fetch pending suggestions
  - `POST /rebooking-suggestions/{id}/approve` 
  - `POST /rebooking-suggestions/{id}/reject`
- [ ] New DTOs defined in `rest-types/src/rebooking.rs`:
  - `ManualRebookingRequestTO` (for manual rebooking requests)
  - `RebookingSuggestionTO` (for suggestion display)
  - `BackfillRequestTO`, `BackfillPreviewTO` (even though these are only for F4, they'll make sense to include now)
- [ ] `ShortEmployeeReportTO` extended with:
  - `has_pending_rebooking: bool` field
  - `pending_rebooking_id: Option<Uuid>` field
- [ ] New route registration in `shifty_bin/src/main.rs`
- [ ] Logic added to compute pending rebooking status in `service_impl/src/reporting.rs`

## Action
1. Create new REST endpoints in `rest/src/rebooking.rs`:
   - Define the endpoint handlers with proper authentication checks and validation
   - Use existing patterns for 409 response handling when slots are taken
   - Implement request/response DTO conversion using existing patterns 
2. Add new DTOs to `rest-types/src/rebooking.rs`:
   - Add structure definitions with appropriate derives (ToSchema, Serialize, Deserialize)
3. Extend `ShortEmployeeReportTO` in `rest-types/src/employee_report.rs`:
   - Add the two new fields with default serde serialization
4. Update `service_impl/src/reporting.rs` to compute pending rebooking status by querying the new DAO method
5. Update `shifty_bin/src/main.rs` to register the new endpoints and route the new service implementation  
6. Add proper #[utoipa::path(...)] annotations to all new endpoints for OpenAPI documentation
